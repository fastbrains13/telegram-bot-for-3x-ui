# Telegram Bot для 3x-ui

[![Node](https://img.shields.io/badge/node-%E2%89%A518.0-green)](https://nodejs.org)
[![Telegraf](https://img.shields.io/badge/bot%20api-telegraf%204-blue)](https://telegraf.js.org)
[![Panel](https://img.shields.io/badge/panel-3x--ui-orange)](https://github.com/MHSanaei/3x-ui)
[![DB](https://img.shields.io/badge/db-sql.js-lightgrey)](https://github.com/sql-js/sql.js)

Бот для Telegram, который берёт на себя регистрацию и поддержку пользователей VPN-панели [3x-ui](https://github.com/MHSanaei/3x-ui): пользователь сам жмёт `/start`, получает клиента сразу во всех инбаундах панели с **одним общим лимитом трафика**, а админ одним движением активирует его, видит дашборд и рассылает новости всей базе.

---

## Возможности

**Пользователь**

- 📝 Саморегистрация через `/start` — клиент создаётся одной записью и привязывается ко **всем** инбаундам панели
- 📏 Лимит трафика по умолчанию **100 ГБ** — **единый на все инбаунды**, а не на каждый (настраивается при установке или командой `/setlimit`; `0` = без ограничений)
- 👥 **Ссылка на Telegram-группу** — кнопка «👥 Наша группа» в меню (если заданы `tg_group_id`/`group_link`); вступление больше **не требуется** для подписки
- ⏸ Новый клиент создаётся **выключенным** — доступ открывается только после активации админом
- 🔗 `/my_sub` (или `/sub`) — **ссылка на подписку** (sub-ссылка `{subURI}/{sub_id}`, а не конфиг)
- 📱 QR-код — по кнопке «Показать QR-код», отдельным сообщением
- 📊 `/stats` — статус, up/down/всего, лимит и остаток трафика (данные берутся из панели)
- 🎛 Все действия — **inline-кнопками**, без ручного ввода команд
- 🤝 Клиент, **заведённый вручную в панели** с указанным Telegram ID, начинает пользоваться ботом без `/start`
- ♻️ **Восстановление подписки** — если клиента удалили в веб-интерфейсе панели, `/start` (или кнопка «♻️ Восстановить подписку») заводит его заново с **тем же `sub_id`**, то есть старая ссылка и QR-код продолжают работать; клиент создаётся выключенным и ждёт активации

**Администратор**

- 📊 `/dashboard` — сводка по панели (Xray, CPU/RAM, версия панели, режим API, онлайн, клиенты, текущий лимит) + **inline-кнопки** для команд
- 👥 `/users` — **все клиенты панели** с **пагинацией по 15 человек**: трафик и **ссылки-команды** «▶️ Включить» / «⏸ Выключить» / «🗑 Удалить» под каждым, навигация «◀️ Назад / Вперёд ▶️»
- ✅ `/enable <tg_id или email>` — активировать одним запросом (панель включает клиента во всех инбаундах)
- 🔴 `/disable <tg_id или email>` — деактивировать
- 🗑 `/delete <tg_id или email>` — удалить клиента из панели и из БД бота
- 📢 `/broadcast <текст>` — рассылка всем пользователям базы
- 🆕 **Уведомление о новом клиенте** — как только в панели появляется клиент (создан ботом или вручную), админ получает сообщение с кнопкой «▶️ Включить»
- 🔄 **Авто-синхронизация статуса** — включили клиента прямо в панели, он включается и в боте (опрос панели каждые `sync_interval_sec`)
- 🏷 **`/setgroup`** — выбор группы клиентов панели, в которую добавляются новые клиенты: список реальных групп с количеством клиентов + создание новой; настраивается и при установке
- 📏 **`/setlimit`** — настройка лимита трафика по умолчанию для новых клиентов: `0` = без ограничений (♾), любое число — ГБ на все инбаунды; быстрый выбор кнопками или командой `/setlimit <число>`

## Требования

| Компонент | Версия / примечание |
|---|---|
| Node.js | **18+** (установщик сам ставит Node 20 через NodeSource) |
| 3x-ui | панель с включённым доступом к API (логин/пароль **или** API-токен) |
| Telegram-бот | токен от [@BotFather](https://t.me/BotFather) |
| ОС | Ubuntu / Debian / CentOS / Rocky / AlmaLinux |

Нативные модули не используются — база данных работает на `sql.js` (WebAssembly-сборка SQLite), поэтому для установки не нужны компиляторы и `node-gyp`.

## Быстрая установка

Скрипт сам размещает проект, создаёт конфиг, ставит зависимости и регистрирует systemd-сервис:

```bash
bash <(curl -sSL https://raw.githubusercontent.com/fastbrains13/telegram-bot-for-3x-ui/main/installer.sh)
```

Из существующего клона:

```bash
git clone https://github.com/fastbrains13/telegram-bot-for-3x-ui.git
cd telegram-bot-for-3x-ui
bash installer.sh
```

> Установщик **интерактивный**: на вопросы о токене, URL панели и ID админа нужно ответить в терминале. От root он дополнительно предложит создать и запустить сервис `tg-bot-3xui`.

### Что спросит установщик

| Вопрос | Пример | Комментарий |
|---|---|---|
| Токен Telegram-бота | `123456:AA...` | получить у @BotFather |
| ID администратора | `123456789` | ваш числовой Telegram ID (@userinfobot) |
| URL панели 3x-ui | `https://vpn.example.com:2053` | протокол + хост + порт панели |
| Базовый путь панели | пусто или `/secret-path` | если у панели скрытый путь |
| Логин / пароль панели | — | вариант аутентификации через cookie |
| API-токен | `3xui-...` | **рекомендуется**; тогда логин/пароль не нужны |
| ID Telegram-группы | `-1001234567890` | (факультативно) группа, куда приглашать пользователей |
| Публичная ссылка группы | `https://t.me/mygroup` | (факультативно) запасной вариант при отсутствии прав на создание приглашений |
| Лимит трафика, ГБ | `100` | единая квота клиента во всех инбаундах (`total` в панели) |
| Путь подписки | `sub` | соответствует настройке *Sub Settings → Path* в панели |
| Группа клиентов панели | `Telegram` | предварительное значение; после установки бот подключится к панели и предложит выбрать группу из реальных (см. ниже) |
| Уведомлять о новых клиентах | `y` | писать админу сообщение при появлении клиента в панели |
| Интервал синхронизации, сек | `60` | как часто опрашивать панель (статусы, новые клиенты) |
| Домен webhook | пусто = long polling | нужен TLS-сертификат и порт, доступный Telegram |

По завершении:

```bash
systemctl status tg-bot-3xui     # состояние
journalctl -u tg-bot-3xui -f     # живые логи
```

### Проверка панели при установке

После установки зависимостей установщик подключается к панели (`node src/setupGroups.js`) и
показывает реальную картину:

```
📋 Клиентов в панели: 24, групп клиентов: 3
   1) "Telegram" — 18 клиентов  ← текущая
   2) "VIP" — 5 клиентов
   3) "(без группы)" — 1 клиент
   🟢 включено: 12, ⏸ выключено: 12

🏷 В какую группу панели добавлять новых клиентов бота?
   номер 1-3 — выбрать существующую
   n<имя> — создать новую, напр. nTelegram
   -      — без группы
```

Выбор сохраняется в `panel_client_group`. Если панель недоступна или запуск неинтерактивный
(`curl | bash`), установка продолжается с значением по умолчанию — группу всегда можно поменять
командой `/setgroup` в боте. Панель создаёт группу автоматически при первом клиенте с таким именем,
предварительно заводить её в веб-интерфейсе не нужно.

```bash
node src/setupGroups.js --print   # JSON: клиенты и группы (без вопросов)
node src/setupGroups.js --set VIP # задать группу из командной строки
```

## Как это работает

Бот определяет версию API панели при входе: если `GET /panel/api/clients/list` отдаёт JSON-массив —
работает современный **clients API** (3x-ui 3.x), иначе откатывается на **legacy** (3x-ui 2.x).

```
пользователь ──/start──▶ бот
                          │ 1. GET  /panel/api/inbounds/list      → список инбаундов
                          │ 2. генерация sub_id                   → ссылка подписки
                          │ 3. POST /panel/api/clients/add        → один клиент со
                          │      { client:{email, subId, tgId,    → totalGB=100 ГБ, enable=false
                          │        totalGB, enable:false},
                          │        inboundIds:[все инбаунды] }
                          │ 4. GET  /panel/api/clients/get/{email} → uuid, выданный панелью
                          │ 5. запись в локальную SQLite
                          ▼
              «аккаунт создан, ждём активации»
                          │
      админ ──/enable <id>▶ 6. POST /panel/api/clients/bulkEnable {emails:[email]}
                          │ 7. уведомление пользователю
                          ▼
        пользователь ──🔗 Подписка──▶ {subURI}/{sub_id} (ссылка на подписку)
                     ──📱 QR-код────▶ отдельное сообщение с картинкой QR
                     ──📊 Статистика─▶ GET /panel/api/clients/traffic/{email}
```

### Фоновая синхронизация с панелью

После запуска бот опрашивает панель (`src/sync.js`, интервал `sync_interval_sec`) и делает четыре вещи:

| Действие | Как |
|---|---|
| Снимок всех клиентов | `POST /panel/api/clients/list` → таблица `panel_clients` в базе бота |
| Статус из панели = истина | если в панели клиент `enable`, а в боте `is_active=0` — флаг обновляется (и наоборот) |
| Ручные клиенты с Telegram ID | клиент, созданный в панели и содержащий `tgId`, импортируется в базу бота — ему доступны `/my_sub`, `/stats`, QR без `/start` |
| Новый клиент | админу приходит `🆕 Новый клиент в панели` с email, лимитом, статусом и кнопкой «▶️ Включить» (дубли исключены флагом `notified`) |

Первый прогон выполняется сразу при старте бота, дальше — по таймеру. Отключить уведомления можно
флагом `notify_new_clients: false`, не трогая саму синхронизацию статусов.

### Почему лимит один на все инбаунды

В 3x-ui 3.x клиент — это отдельная сущность, а не запись внутри каждого inbound. Таблица
`client_traffics` в базе панели имеет `UNIQUE` индекс по `email`, поэтому на клиента существует
**ровно одна строка трафика**:

```sql
-- internal/xray/client_traffic.go
INSERT INTO client_traffics (email, total, up, down, enable)
VALUES (?, ?, 0, 0, ?)
ON CONFLICT(email) DO UPDATE SET total = ?, enable = ?, ...
```

Отсюда следуют два свойства, которые и дают «общий» лимит:

| Поле | Поведение |
|---|---|
| `total` | одна квота на клиента — сколько бы инбаундов к нему ни было привязано |
| `up` / `down` | суммируются по трафику **со всех** инбаундов этого клиента |

Поэтому 100 ГБ, заданные при регистрации, расходуются суммарно: скачал 60 ГБ через VLESS и 35 ГБ
через Trojan — остаток 5 ГБ, а не 175 ГБ. Панель сама выключает клиента при перерасходе.

> ⚠️ В API поле называется `totalGB`, но хранит **байты**: `107374182400` = 100 ГБ.
> В боте это учитывается — `default_traffic_gb` из конфига пересчитывается в байты автоматически.

## Команды

| Команда | Кто | Описание |
|---|---|---|
| `/start` | все | регистрация |
| `/my_sub`, `/sub` | активные | **ссылка на подписку** `{subURI}/{sub_id}` |
| `/stats` | все | трафик и остаток общей лимита |
| `/help` | все | как пользоваться (без админ-раздела) |
| `/dashboard` | админ | сводка + команды админа с описаниями |
| `/users` | админ | **все клиенты панели** (пагинация по 15), ссылки вкл/выкл/удалить |
| `/enable <tg_id или email>` | админ | включить подписку |
| `/disable <tg_id или email>` | админ | выключить подписку |
| `/delete <tg_id или email>` | админ | удалить клиента из панели и БД |
| `/setgroup [<имя>]` | админ | группа панели для новых клиентов: без аргумента — экран выбора из реальных групп, с аргументом — сразу задать (`-` = без группы) |
| `/setlimit [<ГБ>]` | админ | лимит трафика по умолчанию: `0` = без ограничений; без аргумента — экран выбора с кнопками |
| `/broadcast <текст>` | админ | рассылка всей базе |

**Inline-кнопки:** «🔗 Подписка», «📊 Статистика», «📱 QR-код», «📖 Помощь» — для всех; «👑 Панель администратора» — админу. В `/users` inline-кнопки только навигационные («◀️ Назад», «🔄 Обновить», «Вперёд ▶️», «👑 Дашборд»), а включение/выключение/удаление — **ссылками-командами** под каждым клиентом: нажатие подставляет `/enable <email>` в поле ввода чата с ботом. В `/dashboard` команды администратора — **inline-кнопками**. В уведомлении о новом клиенте кнопка «▶️ Включить» — inline.

Админ определяется по числовому `admin_tg_id` из конфига — команды админ-раздела для остальных недоступны.

## Настройка панели и Telegram

**API-токен 3x-ui** (рекомендуемый способ вместо логина/пароля)
Панель → *Settings* → *Security* → *API Tokens* → создать токен со скоупом `admin`. Plaintext показывается один раз — вносите его сразу при установке.

**Путь и адрес подписки**
Ссылка подписки **не равна** адресу панели: у подписки свой порт (`subPort`), свой путь (`subPath`) и иногда
отдельный домен. Бот получает готовый базовый адрес из настроек панели — `POST /panel/api/setting/all` →
поле `subURI` — и добавляет к нему `sub_id`:

```
https://vpn.example.com:40840/x_wEG0r1YC/<sub_id>
        └── subURI из настроек панели ──┘└ sub_id ┘
```

Если эндпоинт настроек недоступен (нет прав у API-токена), адрес собирается из `subDomain` / `subPort` /
`subPath` / сертификатов, а при полном неудачном раскладе — из `panel_url` + `sub_path`.
Поэтому `sub_path` в конфиге — только запасной вариант; достаточно, что путь подписки настроен в самой панели.

**ID администратора**
Напишите [@userinfobot](https://t.me/userinfobot) и скопируйте числовой ID.

**Группа для пользователей (по желанию)**
1. Создайте группу и добавьте в неё бота.
2. Узнайте ID: перешлите сообщение из [@getmyid_bot](https://t.me/getmyid_bot) — ID супергруппы начинается с `-100`.
3. Впишите `tg_group_id` при установке (или позже в `data/config.json`).
4. Укажите `group_link` (публичная ссылка `https://t.me/...`) — с ним в меню появляется кнопка «👥 Наша группа».

Вступление в группу **не требуется**: регистрация, подписка, QR и статистика работают независимо от
членства. `tg_group_id` и `group_link` нужны только для кнопки-приглашения в меню.

**Группа клиентов в панели 3x-ui**
Поле `group` у клиента панели — это метка для сортировки в веб-интерфейсе (вкладки «Telegram», «VIP» и т.д.). Бот проставляет её новым клиентам из `panel_client_group`; настраивается при установке и командой `/setgroup` — без рестарта сервиса:

- `/setgroup` — экран со всеми группами панели и количеством клиентов, выбор нажатием;
- `/setgroup VIP` — сразу задать группу (существующую или новую — панель создаст её при первом клиенте);
- `/setgroup -` — создавать клиентов без группы.

Существующих клиентов бот не переносит — меняется только группа для новых регистраций.

## Конфигурация

Файл `data/config.json` (создаётся установщиком, права `600`):

```json
{
  "bot_token": "123456:AA...",
  "admin_tg_id": "123456789",
  "panel_url": "https://vpn.example.com:2053",
  "panel_base_path": "",
  "panel_username": "admin",
  "panel_password": "secret",
  "api_token": "",
  "tg_group_id": "-1001234567890",
  "group_link": "https://t.me/mygroup",
  "default_traffic_gb": 100,
  "sub_path": "/sub",
  "panel_client_group": "Telegram",
  "notify_new_clients": true,
  "sync_interval_sec": 60,
  "webhook_domain": "",
  "webhook_secret": "",
  "webhook_port": 8443
}
```

Изменить лимит, группу, токен панели или путь подписки можно редактированием этого файла и перезапуском сервиса — пересобирать ничего не нужно.

| Ключ | Значение |
|---|---|
| `panel_client_group` | имя группы клиентов в панели (`group` у клиента) — куда попадают новые клиенты; меняется `/setgroup` без рестарта |
| `notify_new_clients` | `false` — не писать админу о новых клиентах панели (синхронизация статусов продолжит работать) |
| `sync_interval_sec` | период опроса панели: снимок клиентов, статусы, уведомления |
| `sub_path` | **только фолбэк**: базовый адрес подписки берётся из `subURI` настроек панели |

База данных: `data/bot.db` (SQLite).
- `users` — клиенты бота: `tg_id`, `email` (`tg_<tg_id>`), `uuid`, `sub_id`, `is_active`, `traffic_limit`, `group_joined`, `group_invite_link`;
- `panel_clients` — снимок **всех** клиентов панели: `email`, `sub_id`, `tg_id`, `enable`, `total`, `up`, `down`, `group_name`, `first_seen`, `notified`.

Миграции схемы (новые колонки и таблицы) применяются автоматически при старте.


### Используемые эндпоинты 3x-ui

**Основной режим — clients API (3x-ui 3.x)**

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/login` | вход по логину/паролю (если не задан API-токен) |
| GET | `/panel/api/clients/list` | определение режима API |
| GET | `/panel/api/inbounds/list` | список инбаундов |
| POST | `/panel/api/clients/add` | создание клиента сразу во всех инбаундах + общая квота |
| GET | `/panel/api/clients/get/{email}` | данные клиента, uuid |
| POST | `/panel/api/clients/bulkEnable` | включить клиента (все инбаунды разом) |
| POST | `/panel/api/clients/bulkDisable` | выключить клиента |
| POST | `/panel/api/clients/del/{email}` | удаление клиента |
| GET | `/panel/api/clients/traffic/{email}` | статистика трафика (одна строка на email) |
| GET | `/panel/api/clients/get/tgId/{tgId}` | клиент по Telegram ID (для ручных клиентов без /start) |
| POST | `/panel/api/setting/all` | настройки панели: `subURI` — базовый адрес подписки |
| POST | `/panel/api/clients/onlines` | онлайн-пользователи |
| GET | `/panel/api/server/status` | состояние Xray, CPU/RAM, версия панели |

**Режим отката — legacy API (3x-ui 2.x)**, выбирается автоматически, если clients API отсутствует:

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/panel/api/server/getNewUUID` | новый UUID клиента |
| POST | `/panel/api/inbounds/{id}/addClient` | добавление клиента **в каждый** инбаунд |
| POST | `/panel/api/inbounds/{id}/updateClient/{clientId}` | включение/выключение |
| POST | `/panel/api/inbounds/{id}/delClient/{clientId}` | удаление клиента |
| GET | `/panel/api/inbounds/getClientTraffics/{email}` | статистика трафика |
| GET | `/panel/api/inbounds/onlines` | онлайн-пользователи |

Полная документация API: [docs.sanaei.dev — 3x-ui REST API](https://docs.sanaei.dev/docs/reference/api/).

## Особенности и ограничения

- **Telegram-группа — по желанию** — бот может показать кнопку «👥 Наша группа» (при заданных `tg_group_id`/`group_link`), но вступление не проверяется и не влияет на выдачу подписки.
- **`/users` показывает всех клиентов панели**, включая заведённые вручную (не только зарегистрированных ботом). Вкл/выкл/удаление — ссылки-команды с email клиента, работают и по числовому `tg_id`. Пагинации нет: блоки склеиваются по лимиту длины сообщения Telegram и отправляются частями с паузой ~1 с между ними (защита от 429).
- **Удалённого в панели клиента бот восстанавливает по `/start`** — заново создаёт запись с прежними `email` и `sub_id`, поэтому ссылка подписки и QR-код не меняются. Пока клиент отсутствует в панели, `/my_sub`, `/stats` и QR отвечают «⚠️ Ваша подписка больше не найдена в панели» с кнопкой «♻️ Восстановить подписку».
- **Ссылка подписки берётся из настроек панели** (`subURI`), а не из `panel_url`: у подписки отдельный порт, отдельный путь и, возможно, отдельный домен. Эндпоинт `subLinks` панели отдаёт готовые конфиги (`vless://…`), а не ссылку на подписку, поэтому бот его не использует.
- **Лимит трафика единый на все инбаунды** — при 3x-ui 3.x (`clients` API). 100 ГБ расходуются суммарно по всем инбаундам клиента, а не по 100 ГБ на каждый. Режим определяется автоматически, `/dashboard` показывает активный режим.
- **На панели 2.x (`legacy` API) общего лимита нет.** Клиент заводится отдельно в каждый инбаунд и у каждого своя строка трафика со своим `total`, то есть при 5 инбаундах суммарно доступно до 5 × 100 ГБ. Это ограничение версии панели — обновите 3x-ui до 3.x, чтобы получить единую квоту.
- **Активировать можно и в панели, и в боте** — статус `enable` из панели синхронизируется с `is_active` бота на каждом проходе опроса, а `/my_sub` и `/stats` сверяются с панелью перед ответом. Кнопки и команды бота по-прежнему остаются основным способом.
- **Протоколы без URL-формы** (socks, http, wireguard, dokodemo, tunnel) также получают клиента — панель для них не формирует ссылку подписки.
- **Рассылка** идёт последовательно по базе и ограничена лимитами Telegram API; на тысячах пользователей добавьте задержку между `sendMessage`.
- **Смена токена/пароля панели** не требует переустановки — достаточно правки `data/config.json`.

## Обновление на сервере через Git

### Если бот уже установлен как git-репозиторий

```bash
cd /root/tg-bot-3xui
git pull
systemctl restart tg-bot-3xui
journalctl -u tg-bot-3xui -n 20 --no-pager
```

`data/config.json` и `data/bot.db` находятся в `.gitignore` — обновление их **не трогает**.
Зависимости подтягиваются только если менялся `package.json`:

```bash
git diff HEAD@{1} HEAD --name-only | grep -q package && npm install --production
```

Проверить, что код действительно обновился:

```bash
git log --oneline -3          # последние коммиты
git status -sb                # ## main...origin/main без изменений
```

### Если установщик создавал файлы напрямую (нет `.git`)

Старые версии `installer.sh` не делали `git clone` — в директории нет репозитория,
и `git pull` выдаст `fatal: not a git repository`. Превращаем установку в репозиторий
один раз, конфиг и база при этом сохраняются (они в `.gitignore`):

```bash
cd /root/tg-bot-3xui
git init
git remote add origin https://github.com/fastbrains13/telegram-bot-for-3x-ui.git
git fetch origin main
git checkout -f -B main origin/main
```

Дальше живут обычные `git pull`.

### Что проверить после любого обновления

1. Сервис поднялся: `systemctl status tg-bot-3xui`, в логе — `✅ Logged in to 3x-ui panel`,
   `🤖 Bot @... is running`, `🔄 Синхронизация с панелью: каждые 60 с` и
   `🔄 Синхронизировано клиентов: N (новых: M)`.
2. Написать боту `/dashboard`: строка `🔌 API:` должна показывать актуальный режим,
   `🗂 Клиентов в панели:` — их число, а команды админа — выводиться списком с описаниями.
3. Проверить `/users`: ссылки «▶️ Включить» / «⏸ Выключить» открывают чат с уже набранной командой.
3. Если менялась схема БД (в README есть соответствующие заметки) — миграции
   применяются автоматически при старте, ничего вручную делать не нужно.

### Откат на предыдущую версию

```bash
cd /root/tg-bot-3xui
git log --oneline -5            # найти хеш рабочей версии
git checkout <хеш>
systemctl restart tg-bot-3xui
```

Чтобы вернуться обратно: `git checkout main`.

## Устранение проблем

| Симптом | Причина и решение |
|---|---|
| `Panel login failed` | неверный логин/пароль или скрытый путь; проверьте `panel_base_path` или используйте `api_token` |
| `Логин панели не вернул JSON (HTTP 404 по адресу ...)` | неверный `panel_url` или `panel_base_path`; путь берётся из *Panel Settings → Base Path* |
| `Config not found. Run installer.` | бот запущен не из корня проекта или отсутствует `data/config.json` |
| `/stats` показывает нули | клиент ещё не активирован или панель не накопила статистику |
| `/users` показывает 1 клиента вместо 25 | обновите бота: `/users` читает список из панели (`/panel/api/clients/list`), а не только локальную базу |
| Ссылка подписки не открывается / не тот порт или путь | базовый адрес берётся из `subURI` настроек панели; проверьте *Sub Settings* (порт, путь, домен, сертификат) в веб-интерфейсе 3x-ui |
| Клиент включён в панели, а бот показывает «не активирована» | дождитесь прохода синхронизации (`sync_interval_sec`) или откройте `/my_sub` — статус сверяется с панелью напрямую |
| `⚠️ Ваша подписка больше не найдена в панели` | клиента удалили в веб-интерфейсе панели. `/start` или кнопка «♻️ Восстановить подписку» заведут его заново с **тем же `sub_id`** — старая ссылка и QR остаются валидными, активация снова за админом |
| `/users` — несколько сообщений подряд | пагинация по 15 клиентов на странице: «◀️ Назад» и «Вперёд ▶️» |
| Пустой ответ панели при добавлении клиента | известная особенность API 3x-ui; обновите панель до актуальной версии |
| Self-signed сертификат панели | `undici` отвергнет соединение — используйте `https` с валидным сертификатом или поставьте панель на домен с Let's Encrypt |
| Webhook не стартует | Telegram требует публичный порт 443/8443/80/8080 и валидный TLS |

## Безопасность

- `data/config.json` содержит секреты — файл закрыт правами `600` и добавлен в `.gitignore`.
- `data/` целиком игнорируется git: база и конфиг не попадут в репозиторий.
- API-токен панели даёт полный доступ к 3x-ui — используйте отдельный токен только для бота и отзывайте его при компрометации.
